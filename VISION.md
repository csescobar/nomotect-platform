# Vision

Rails Hotwire Platform is an AI-First Enterprise Application Platform for building secure, governed, accessible and maintainable business applications with Ruby on Rails and Hotwire.

## What AI-first means

AI-first does not mean that the platform is generated by AI or that human review is optional. It means that the architecture, documentation, APIs, tests and governance are intentionally designed so both humans and coding agents can understand and extend the system safely.

The platform should reduce the amount of implicit knowledge required to make a correct change. Important concepts must be explicit, discoverable, testable and documented close to the code they govern.

## Target users

- Teams building enterprise Rails applications
- Solo developers who need strong defaults and governance
- Organizations adopting agent-assisted engineering
- Maintainers inheriting long-lived business systems
- Contributors who do not have access to proprietary codebase-memory tools

## Core promises

1. **Explicit architecture** — domains, operations, policies, events, components and extension points are identifiable.
2. **Machine-readable context** — modules expose contracts that tools and agents can consume.
3. **Safe defaults** — security, privacy, tenant isolation, authorization, auditability and accessibility are built in.
4. **Executable guidance** — examples, tests, generators and validation commands document the intended approach.
5. **Human accountability** — AI-assisted changes remain subject to review, evidence and governance.
6. **Long-term maintainability** — decisions and constraints remain understandable after the original authors leave.

## Enterprise principles

- Modular monolith before distributed architecture
- Rich domain behavior rather than unrestricted record mutation
- Server-rendered HTML with progressive enhancement
- Open-source dependencies by default
- Internationalization from the first implementation
- Structured logs separated from audit records
- Privacy and security impact considered for every feature
- Stable public contracts and explicit deprecation paths

## Non-goals

The platform is not intended to:

- Replace Rails conventions with a custom framework everywhere
- Generate entire applications without review
- Require a specific AI vendor or proprietary agent workflow
- Hide complexity behind opaque metaprogramming
- Treat documentation as a substitute for tests
- Introduce microservices before operational need exists

## Success criteria

The platform succeeds when a contributor or coding agent can:

- Identify the responsible module for a requested change
- Understand its invariants and allowed dependencies
- Locate extension points and prohibited modifications
- Implement the change using documented patterns
- Run deterministic validation
- Produce security, privacy, accessibility and operational evidence
- Submit a reviewable pull request without relying on undocumented project knowledge
